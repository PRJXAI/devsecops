# Release unblock work — 2026-10-28

## Independent release scope — implemented; hosted preparation exercised

At the owner's request, the former nine-image/eighteen-handoff publication unit is replaced by **one tool, two native architectures**. `.github/workflows/ci.yml` calls `.github/workflows/tool.yml` independently per selected tool. `fail-fast: false`, per-tool concurrency, exact tool/architecture artifact names and each invocation's own native-job dependency prevent cargo-deny, kind or a failed experimental Gitleaks job from vetoing a different tool's release. Shared source checks/dependency audit and required pinned scanner/DB setup remain mandatory.

Each tool has its own `.github/publication-readiness/TOOL.json`, GHCR repository and publish/attestation output. `catalog-tool TOOL`, `prepare-tool TOOL` and `publish-tool TOOL` reject unknown identities. Publication requires the selected tool's readiness, tool-and-source-bound manual approval, both fresh verified handoffs, and both successful actual archive loads before any tag/push. There is no one-architecture route, wildcard artifact substitution or aggregate approval fallback. The aggregate publication CLI is retired; the old global readiness path holds only a schema-0 retirement marker, which also rejects use by the old publisher. It supplies no approvals or fallback.

This closes the **cross-tool coupling defect**, not the remaining acceptance blockers. All nine tools still have unresolved evidence in their own readiness record. No readiness approval has been invented or set true. The subsequent owner decision now permits [explicitly reviewed no-fix/no-viable-alternative risks](release-risk-policy.md) without labeling them clean. Hosted run 40712836198 exercised the new workflow at source `818c362`: both Gitleaks production jobs passed despite all eight other tool releases failing preparation. Registry publication/attestation remains unverified; exact evidence is in [results](results.md).

The tested Gitleaks source/dependency upgrade is now wired into **production packaging and inventory**. Local arm64 `prepare-tool gitleaks` passes with one accepted-risk finding, zero blocking findings and checked Go notices. This does not convert historical candidate artifacts into release handoffs. Clean-source hosted production handoffs now exist for both architectures at `818c362`; exact source/legal review and publication/attestation acceptance remain missing. An earlier separate local candidate rerun reproduced a clean-working-tree completion stall and failed closed; the subsequent hosted successes do not establish that its cause is resolved.

The 2026-10-29 [source follow-up](../licenses/gitleaks-runtime-review.md) now captures exact expanded public APK recipes and 20 selected payload bindings for both hosted architectures. Source-overlay contents and complete notices/delivery/review remain incomplete. A separate [loader-only diagnostic](runtime-completion.md) reproduces the timeout without executing Gitleaks/Git, narrowing the investigation to the loader/runtime/host boundary without identifying a fix.

## Native-candidate step and current production reuse

`src/gitleaks_candidate.rs` now shares the same fixed-source builder between production and the separate opt-in evidence test; it supplies no publication approval. It retrieves the fixed source into capped private capture, checks the source/patch/manifests, and uses a digest-pinned Go 1.27.3 container. Only module retrieval has network access; the owned build container is explicitly disconnected before module verification, the complete upstream race suite and compilation. Source/cache tmpfs, CPU/memory/PIDs, process deadlines and unconditional container removal are bounded. No host configuration or Docker socket is supplied to that container.

The evidence test retains an explicit hash-reviewed fixture Dockerfile and experimental label. Production has its own exact reviewed recipe and private context; both package only the verified executable, checked Go notice bundle and existing pinned runtime closure. General local COPY/RUN policy is not expanded. Input hash/create-only/nofollow and fixture mutation negatives persist in ordinary tests. Every compiler/manifests/version/module expectation is literal and narrow; this is not a general supplier-rebuild framework.

An initial local attempt passed upstream race tests and compilation, then failed because Docker copy could not see the live tmpfs output. The failed measurement/status is retained. That is **functional/inventory evidence only**; no vulnerability scan or release approval is implied.
